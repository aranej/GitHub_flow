COMMIT MESSAGE FORMAT
════════════════════════════════════════════════════════════════════════════
feat(scope):    → Bumps MINOR version (new feature)
fix(scope):     → Bumps PATCH version (bug fix)
feat!:          → Bumps MAJOR version (breaking change)
BREAKING CHANGE:→ Bumps MAJOR version (in commit body)
docs:           → No version bump
chore:          → No version bump
style:          → No version bump
test:           → No version bump

GOOD EXAMPLES:
  git commit -m "feat(auth): add OAuth2 support"
  git commit -m "fix(ui): button alignment issue"
  git commit -m "feat!: redesign API endpoints"

BAD EXAMPLES:
  "updated code" ✗
  "Feat: Added feature" ✗
  "feat: add feature." ✗

QUICK START (30 MINUTES)
════════════════════════════════════════════════════════════════════════════

OPTION A - Single NPM Package:
  1. npm install --save-dev semantic-release @semantic-release/github
  2. Copy .releaserc.json to your project
  3. Copy .github/workflows/release.yml to your project
  4. npx semantic-release --dry-run
  5. git add . && git commit -m "chore: setup releases"
  6. git push
  7. Make a feat commit to trigger first release

OPTION B - Monorepo with pnpm:
  1. npm install -g pnpm
  2. pnpm add -D @changesets/cli @changesets/changelog-github
  3. pnpm changeset init
  4. Copy .changeset/config.json to your project
  5. Copy .github/workflows/changesets-release.yml
  6. pnpm changeset  (preview version bump)
  7. git push (GitHub Action creates release PR)

OPTION C - Manual with Release Drafter:
  1. npm install --save-dev release-drafter/release-drafter
  2. Copy .github/workflows/release-drafter.yml
  3. Copy .github/release-drafter.yml
  4. Add GitHub labels: feature, bugfix, breaking, docs
  5. Push to main with proper PR labels
  6. Draft release auto-updates
  7. Publish manually when ready

GITHUB CONFIGURATION
════════════════════════════════════════════════════════════════════════════

SECRETS (Settings → Secrets and variables → Actions):
  □ NPM_TOKEN       (from npmjs.com, scope: publish:all)
  □ PYPI_TOKEN      (if publishing to PyPI)
  □ GITHUB_TOKEN    (auto-created, verify permissions)

BRANCH PROTECTION (Settings → Branches → main):
  □ Require pull request reviews: 1+
  □ Require status checks to pass
  □ Restrict who can push: Add github-actions[bot]
  □ Allow deletions: OFF
  □ Allow force pushes: OFF

ACTIONS PERMISSIONS (Settings → Actions → General):
  □ Read and write permissions: ON
  □ Allow PR approvals: ON

TROUBLESHOOTING
════════════════════════════════════════════════════════════════════════════

Release not creating?
  → Check commit message format (must start with feat:, fix:, etc)
  → Verify you're pushing to main branch
  → Check GitHub Actions logs

Wrong version bump?
  → Verify commit type (feat = minor, fix = patch)
  → Check for BREAKING CHANGE in commit body
  → Test locally: npx semantic-release --dry-run

Publishing failing?
  → Verify NPM_TOKEN is set and valid
  → Check token has publish scopes
  → Verify package.json is correct

GitHub Action failing?
  → Check workflow YAML syntax (indentation)
  → Verify all secrets are configured
  → Check branch protection settings
